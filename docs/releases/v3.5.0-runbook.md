# v3.5.0 release runbook

Bundles GitHub issues [#58](https://github.com/MikeBild/subkit/issues/58) +
[#59](https://github.com/MikeBild/subkit/issues/59). Migrates non-bootstrap
runtime configuration out of `.env` into `subkit.config.json` (validated
via Zod, written via `sk settings configure` / `PUT /v1/settings/{path}`,
auto-generated session secret, atomic writes, per-tenant overlay,
`SK_OVERRIDE_<KEY>` env escape hatch).

## Cut-the-release checklist

Operator runs this from the v3.5 branch on a clean working tree.

1. **Pre-migration export (v3.4.x operators only)**
   ```sh
   bun run apps/engine/scripts/export-legacy-settings.ts > legacy-settings-export.json
   ```
   Reference this file when populating `subkit.config.json`. The file is
   **secret** — delete it once the upgrade is complete.

2. **Quality gate**
   ```sh
   bun run verify
   ```
   Includes lint, typecheck, terminology, recipe-lint, audit-invariants,
   `check:settings-doc-drift`, determinism, full unit suite, eval, build:sk,
   and e2e against the compiled binary.

3. **Issue label flip**
   ```sh
   gh issue edit 58 59 --remove-label release/v1.1 --add-label release/v3.5
   ```

4. **Version bump + binaries + Docker images + droplet deploy**
   ```sh
   scripts/deploy.sh minor
   ```
   This bumps `3.4.1` → `3.5.0`, builds 12 CLI binaries × platforms,
   builds `engine` + `migrate` + `engine-with-cli` Docker images, pushes
   to DOCR, deploys to the droplet, runs `scripts/release/verify.sh`.

5. **Post-deploy probes** (covered by `scripts/release/verify.sh`; manual
   spot-check):
   - `/v1/health` reports `3.5.0`
   - `/v1/diagnostics/setup` reports no parse errors and no pending restarts
   - `sk settings list` returns the new envelope (`items` with `_meta` per leaf, plus `diagnostics`)
   - `sk settings set llm.api_key '"…"'` round-trips and emits a `settings.changed` audit row
   - Restart probe with `SK_OVERRIDE_LLM_API_KEY=test` shows `source: "override"` for that key

6. **Release notes** — lead with the operator-UX outcome (per the
   "enterprise business value first" rule):
   > _"Rotate keys without editing `.env`. See an audit trail of every
   > settings change. Restart only when truly required."_

## Known v3.5 → v3.6 follow-ups

- **Granular RBAC scopes** — `settings:read:tenant` /
  `settings:write:global` planned; v3.5 keeps the existing
  `settings:read` / `settings:write` permissions and enforces tenant-scope
  policy at the route handler.
- **Watch-mode hot reload** — c12's `watchConfig` is wired in but
  disabled in v3.5 because the audit story for direct file edits needs
  one more pass; all runtime changes must go through `setConfigKey` for
  v3.5.

## Rollback

The migration is `ALTER TABLE tenants DROP COLUMN settings`. Recovery
requires restoring the column from a pre-migration backup; subkit does
not ship a generated rollback migration. Per the project's "no
backwards-compat shims" rule, the v3.4.x → v3.5 path is forward-only.
