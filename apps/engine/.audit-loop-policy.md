# Audit-Loop Policy (STOP signals)

This file is the canonical list of actions the **audit closed-loop driver** is
**forbidden from taking**, even when its CI pipeline is green and the change
would otherwise be mechanical.

The point of these signals is to keep the loop from silently lowering the safety floor
to make itself look productive. Every item below is a HUMAN-ONLY decision.

If the loop encounters any of these, it MUST:
1. Park the in-flight PR with the `audit-blocked` label.
2. Open a `needs-human` issue describing the obstacle and the last green `main` SHA.
3. Move on to the next independent change in the current phase.

## Forbidden actions

1. **Adding any line to `apps/engine/.size-allowlist.txt`.** If a generated change pushes
   a file over 1000 LOC, the loop must split first, not allowlist.
2. **Lowering any value in `apps/engine/.coverage-floor.json`.** The loop may only RAISE
   floors, never lower them.
3. **Adding any line to `apps/engine/.tenant-filter-allowlist.txt`.** Tenant-filter
   exemptions are security-sensitive.
4. **Creating a new top-level directory under `apps/engine/src/`.** The
   `no_new_subsystem` invariant blocks this; the loop must not edit
   `tests/contract/subsystem-count.test.ts` to compensate.
5. **Importing `@ai-sdk/*` outside `apps/engine/src/llm/core/`.** The loop must not edit
   the lint config to allow the import.
6. **Editing `tests/journeys/session-*-regression.*`.** These tests pin behaviour. The
   loop must change code so they pass, not change them so the code passes.
7. **Suppressing a CI check** via `// eslint-disable`, `// biome-ignore`,
   `bun:test only`, or any equivalent. Banned entirely.
8. **Force-pushing to `main`** or **bypassing required CI**. Never.
9. **Reaching the per-PR retry budget** (default 3). Pause and file a `needs-human` issue.
10. **Recipe-sweep step-kind design decisions.** The loop generates a skeleton PR and
    STOPS; product input drives the step-kind shape.

## Operator override surface

The operator has three levers without taking the system out of closed-loop mode:

- Comment `/audit pause` on issue #66 — loop drains in-flight PRs and stops at the next
  phase boundary.
- Comment `/audit skip <change-id>` on a parked PR — loop closes the PR and moves on.
- Add the `audit-loop-keep-open` label to any PR — loop will not auto-merge that PR even
  if CI is green; treats it as human-owned.

Anything beyond these (changing phase order, lowering a coverage floor, adding to size
allowlist) is a regular PR reviewed by the operator. The loop reads these files but
never writes to them.

## Forensic trail

Every loop action is recorded in `audit/` with `request_source = "audit-loop"`. The
operator can reconstruct the full action history from the audit log without trusting
the loop's self-reporting.
