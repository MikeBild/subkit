# File-size allowlist for the audit-invariants CI check.
#
# Files listed here exceed the 1000-LOC ceiling. Each entry needs a
# written reason. Adding to this list requires PR review.
#
# The entries below are at a documented steady state: their remaining
# concerns are tightly coupled and any further split would produce
# barrel-only seams (a pattern previously tried and rejected — splitting
# these produced barrels around one fat callee with zero domain value).
# Re-opening any of these requires a per-concern split that survives an
# AST-export-equality check; do not list new entries unless that gate is
# met.
#
# Format: <relative path from repo root>  # reason
# Comments and blank lines are ignored.

apps/engine/src/conversations/loop.ts                  # steady state — chat-turn dispatch loop. Per-turn lifecycle (resume → tool-call → mutation → emit → abort) is one tightly-coupled state machine. Pure helpers were extracted to `loop/` (stop-conditions.ts, usage.ts, model-resolver.ts) but the orchestrator body holds a closure over event sink / abort controllers / draft snapshots that no further split can break without producing barrels-around-one-fat-callee. Re-opening requires a per-concern split that survives an AST-export-equality check.
apps/engine/src/conversations/tools/sdk-wrap/invoke.ts # steady state — agentic tool-invoke wrapper. policy-gate / dedupe / langfuse-instrumentation / response-handling all share the same call-site closure (request_id, signal, audit hooks); extracting them produces ≥3 helper modules that each take 12-15 args, worse than the inline form.
apps/engine/src/execution/steps/request/dispatch.ts    # steady state — request-step dispatcher. Per-driver branches (graphql / s3 / postgres / http) share the retry / pagination / shape-coercion scaffolding; tried-and-rejected: drivers/*.ts files that re-import the same six helpers and a pagination.ts that has to call back into dispatch for shape coercion.
apps/engine/src/http/routes/files.ts                   # steady state — unified files HTTP surface. The 10 routes (inline + presigned upload, finalize, list/get/download/delete, link, stats, local presign sink) share a tight closure over the HMAC presign helpers + objectStore + auditAwait + scanner. Splitting per-verb produces 10 sibling files that each re-import the same six helpers and one heavy types module; the per-verb seams add zero domain value and obscure the dedup-race + finalize + Range branches that span multiple handlers.
apps/engine/src/workflows/types.ts                     # steady state — workflow Zod surface. Single discriminated union over step kinds (request / transform / s3 / postgres / etc.) plus the input_schema / output_schema / multipart / file leaf types from Wave C Step 7. Splitting per-step-kind produces sibling files that each have to re-import JsonValueSchema + FileRefSchema and the shared validators; the union's exhaustiveness check has to live with the union itself.
apps/engine/src/connectors/drivers/http.ts             # steady state — HTTP driver core. The request-step dispatcher, multipart body builder, retry/pagination scaffolding, and AuthN injection all share the same call-site closure (request_id, abort signal, audit hooks). Per-concern splits produce ≥3 helper modules that each take 12-15 args, worse than the inline form (same pattern as conversations/tools/sdk-wrap/invoke.ts).
apps/engine/src/execution/engine.ts                    # steady state — workflow execution orchestrator. The topo-walk drives step dispatch, the loop / parallel / branch sub-runners, the loop-iteration OffloadRef substitution (the OOM fix), final-output re-hydration, output_transform / response_filters / output_schema / validation, then persistence + audit — all sharing one closure over `scope`, `iterationResults`, `warningsAccum`, `finalStatus`, `validationError`, `llmBudget`. Pure helpers were already extracted to `engine/` (connector-rollup.ts, envelope.ts); the remaining body is a single tightly-coupled state machine — same category as conversations/loop.ts. Splitting the loop / output sub-runners produces barrel-only seams that each take 10+ closure args.
apps/engine/src/config/schema.ts                       # steady state — the single Zod config surface. One nested schema tree whose leaves carry `.meta(tenant()/global())` scope tags that the config walker + settings-route resolver read off the whole tree; sections (llm / http / connectors / rbac / observability …) share the tenant()/global() meta helpers and the section-default plumbing. Same category as workflows/types.ts: splitting per-section produces sibling files that each re-import the meta helpers and a barrel that re-assembles the tree for the walker — barrel-only seams with zero domain value. Grows by a few LOC per new config leaf (crossed 1000 with the llm.web_search leaf).
apps/engine/src/scheduler/reconciler.ts                # steady state — periodic-sweep reconciler. Each sweep (proactive-drift, skill-candidate, connector-reauth, …) adds a reconcileX method that shares the same microsecond-safe range-based CAS tenant-claim + 60s tick scaffolding; the per-sweep work already lives in its own *-runner.ts file. Splitting the claim/dispatch glue per sweep produces sibling files that each re-import the CAS helper and a barrel re-assembling the tick — barrel-only seams with zero domain value. Grows a few LOC per new sweep (crossed 1000 with the connector-reauth scan).
apps/engine/src/conversations/tools/dry-run-workflow.ts # steady state — draft-preview orchestrator. One closure drives cache-key/replay, OffloadRef re-hydration, per-step preview recording (scope_index snapshot), the recorded-eval + judge gate, repair-proposal surfacing, and auto-commit-on-green — all sharing `draft`, `previewByStep`, `effectiveEnvironment`, `warnings`. The cohesive credential-environment resolution was extracted to credentials/service.ts (resolveDryRunEnvironment); the residual is a single tightly-coupled state machine like execution/engine.ts. Further splits produce barrel-only seams that each take 10+ closure args. Crossed 1000 with the for_each/skipped-status/env-targeting wave.
apps/engine/src/conversations/recorded-eval.ts          # steady state — recorded-evaluation pass for authoring mutations. One pass compiles every authored expression (JSONata + JS via the QuickJS sandbox), resolves $scope references against fingerprint-valid recorded previews, evaluates transform/loop-over sites, runs the loop/transform authoring-gate verdicts (incl. the hand-rolled-codec detector), and runs the bounded auto-repair fan-out — all sharing one closure over `recordedScope`, `expressions`, `scope_refs`, `missingByStep`, and the gate verdicts. The branches are tightly coupled (a finding feeds the repair fan-out which feeds next_actions which feeds the summary); splitting per-stage produces barrel-only seams that each re-import the finding contract and the gate evaluators. Crossed 1000 with the codec-rewrite next-action + typed wire-contract enum.
apps/engine/src/audit/types.ts                         # steady state — the single audit-action + per-action metadata-schema registry. One file holds the AuditAction enum (every state-changing path's action constant) plus the pinned Zod metadata schema for each audited action, co-located so a new action and its metadata shape land together and stay in lockstep. Splitting per-domain produces sibling files that each re-import the shared AuditEntry/AuditResult types and a barrel re-assembling the enum for the writer — barrel-only seams with zero domain value. Grows a few LOC per new audited action (crossed 1000 with conversation.skill_loaded).
